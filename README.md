# my-next-app

Практическая работа по курсу Next.js: структура проекта, Server и Client Components.

## Как запустить

```bash
npm install
npm run dev
```

Открыть http://localhost:3000

## Что внутри

- `/server-demo` — Server Component (async, время с сервера)
- `/client-demo` — Client Component (`use client`, счётчик кликов)
- `/greet-demo` — Server Function (`use server`, приветствие с сервера)
- `/about` — статическая страница
- `/blog` — список постов, `/blog/[id]` — пост, `/blog/[id]/comments/[commentId]` — комментарий
- `/courses` — раздел курсов с layout'ом, `/courses/[id]` — страница курса
- `/products/[id]` — сервер получает товар, кнопка в корзину — клиент

## Ответы на вопросы самопроверки

**1. Какую роль играют папки app/, public/ и файл next.config.js?**
`app/` — маршруты и страницы (App Router), `public/` — статика (картинки, favicon), `next.config.js` — настройки Next.js.

**2. Какие файлы в App Router делают маршрут публичным, а какие создают общий UI?**
`page.tsx` делает маршрут публичным (UI конкретного URL), `layout.tsx` — общий UI для сегмента (навигация, футер).

**3. В чём разница между Server и Client Component с точки зрения выполнения?**
Server выполняется только на сервере, его код не уходит в браузер. Client рендерится на сервере в HTML, но потом гидратируется в браузере и может использовать хуки.

**4. Когда нужна директива 'use client'?**
Когда компонент использует хуки (useState, useEffect) или обработчики событий (onClick). Ставится первой строкой файла.

**5. Как создать динамический маршрут и получить параметр в Next.js 15?**
Папка с квадратными скобками `[slug]`, в компоненте `params` — это Promise, его нужно await-ить: `const { slug } = await params;`

**6. Что такое generateStaticParams?**
Функция, которая при сборке перечисляет значения динамических сегментов, чтобы Next.js заранее сгенерировал статические HTML для них.

**7. Почему Server Components не увеличивают клиентский бандл?**
Их код выполняется на сервере и никогда не попадает в бандл браузера — в клиент отправляется только готовый HTML.

## Практическая работа 2: маршрутизация и навигация

**1. Как Next.js определяет URL страницы на основе структуры папок?**
Структура папок внутри `app/` повторяет URL: папка = сегмент маршрута, а файл `page.tsx` делает этот сегмент доступным по адресу.

**2. Чем отличается layout.tsx от template.tsx?**
Layout сохраняется при навигации между дочерними страницами (не перемонтируется), template создаётся заново при каждом переходе. Layout — для общей обёртки, template — когда нужно сбрасывать состояние или запускать анимации.

**3. Как создать динамический маршрут и получить значение сегмента в компоненте?**
Папка с квадратными скобками `[id]`, значение сегмента приходит в пропс `params`, в Next.js 15+ это Promise, поэтому `const { id } = await params;` внутри async компонента.

**4. Почему для внутренних ссылок рекомендуется использовать Link, а не a?**
`<Link>` из `next/link` перехватывает клик и делает переход на стороне клиента без полной перезагрузки страницы, плюс сам предзагружает страницы.

**5. Как получить параметры динамического маршрута в клиентском компоненте?**
Пропс `params` в клиентские компоненты не передаётся — используется хук `useParams()` из `next/navigation`, типизируется через generic: `useParams<{ id: string }>()`.

**6. Что произойдёт, если в app/blog/ создать layout.tsx, а затем перейти с /blog на /blog/1?**
Блог-layout обернёт обе страницы (они дочерние сегменты одного уровня) и сохранится при переходе — /blog/1 отрендерится внутри того же layout, без перемонтирования.

**7. Как организовать вложенные динамические сегменты?**
Папки вкладываются друг в друга: `app/blog/[id]/comments/[commentId]/page.tsx`, в `params` будут оба ключа: `{ id, commentId }`.

**8. Почему в Next.js 15+ params объявлен как Promise?**
Чтобы страница могла дождаться загрузки данных маршрута (например, вложенных сегментов или searchParams) и это совместимо с подходом async компонентов и streaming.
